# Strategic step

Adapted from Matt Pocock's chief-of-staff skill (MIT). Each ticket answers the tactical question. This step asks the second one: what change to the environment would make the next ticket cheaper?

Read this after you close a ticket.

## What to look for

- A check that would catch the problem the ticket found (a name-alignment check, a count check, a data-contract-check row).
- A lint or convention that makes the right move the easy one (a theme file, a naming rule in the analysis doc).
- A data access that was missing (a path, a permission, a transfer, a sample sheet).
- A recurring chore a schedule could do (a status check on a long SLURM job, a weekly look at the map).
- A workaround you just used. Do not repeat it. Fix the cause or ticket the fix.

## Where it goes

- Small and clear: one `Strategic: <change>, because <what it saves>` line in Notes.
- Needs work or the user's call: a new `task` ticket, blocked by nothing or by what it truly needs.
- Nothing found: write `Strategic: none` in the Resolution so the next session sees the question was asked.

Do not carry out the change in the same session unless it is the ticket. Edits to gated code still need an approved plan.
