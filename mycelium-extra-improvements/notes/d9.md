1. `feat(plan-review): flag defaults without a reason (D9)`
   - New skills/plan-review/scripts/default_reasons.py. Stdlib, 3.6 grammar, runnable from stdin as
     `python3 - --plan <(cat <<'EOF' ... EOF) < default_reasons.py`. `check_plan(plan)` returns
     (tables, defaults, flags), and each flag is {row (first cell), step, column, line, text, problem}. `describe()` and
     `render()` produce plain text (no Markdown). Exit codes: 0 means checked (with or without flags), 1 means the plan
     could not be read, and 3 means no plan table was found (not checked, so not clean).
   - Matching rules:
     - Only the Source column is read when the table has one. If it has none, every cell is read. This means
       `k (default: 10)` in a Choice column is not a source.
     - `default:` is matched case-insensitively. Its reason runs to the next `repo:`/`default:` in the same cell.
     - Problems are checked in this order:
       - "no reason": nothing is left after punctuation and FILLER (a, an, the, is, it, its, it's, this, that, just, and, or).
       - "an empty phrase, not a reason": an EMPTY_PHRASES phrase was removed, and fewer than 3 other words remain. The match is case-insensitive, on whole words, with an optional plural "s", so `Standard.`, `(standard)`, `best practices`, `standard choice` and `it's standard` all count.
       - "a reason under 3 words".
     - `matches step 2` (C1 fixture row 3) and the BH acceptance reason are not flagged.
   - The EMPTY_PHRASES list (exactly the four in the roadmap) and MIN_WORDS sit at the top of the module. This meets the "one file a user can read and extend" constraint.
   - plan-review SKILL.md, section 1: a new bullet runs the check on the draft. It is advisory and never blocks. Its output goes in the packet's `unknowns:` and in the report, and flagged rows become proposed amendments. Exit 3 or a failed run must be reported as "not run", never as clean.
   - Tests:
     - New skills/plan-review/tests/test_default_reasons.py has 9 tests: the acceptance rows, phrase variants, short and missing reasons, passing reasons, column scoping, CLI from stdin with plain-text output, and the CLI gap and read-error exits.
     - test_plan_review.py has one new case, as the roadmap's Tests line asks.

## Deviations / maintainer decisions
- The minimum is 3 words. "A few words" is not defined in the roadmap. 3 keeps the C1 fixture's `default: matches step 2` clean, and it flags
  `Seurat default`. The value can be changed in MIN_WORDS.
- Only the plan table is checked. The roadmap also wants a one-line Assumptions entry per default, but that is not checked, because the scope says each flag names a plan row.
- A missing checker in verify is a gap, so it changes the status to CONFORMS_WITH_GAPS (see the precedent above). If the
  maintainer wants advisory-tool absence to leave the status unchanged, change "gap" to "info" in default_reasons() and
  update test_missing_checker_is_a_gap and test_broken_checker_is_a_gap.
- The grill row is now `partial: verify (...)`, although verify only reports this as `info`. The plan must still write
  parameters out, and the bracket text says the check is advisory.
- Outside my ownership list, in files beyond the three commits' named targets: skills/verify/SKILL.md (one paragraph)
  and skills/plan-review/tests/test_plan_review.py (one test, which the roadmap asks for). test_verify.py was not edited.
  Expect a trivial merge with the E workstream only if it also edits verify SKILL.md near "The report ends with".

## Known limitations
- Heuristic: a 3-word non-reason such as "used by everyone" passes, and the check never judges whether a reason is correct (out of scope).
- The scaffold placeholder `[repo: / user / default:]` (new_analysis.py) is flagged as "no reason". This is intended, because an unfilled placeholder has no reason.
- Plain-text CLI output wraps the cell text in double quotes. The verify findings are in the Markdown report, like other findings.
